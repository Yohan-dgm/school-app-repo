## 3. Network Resilience & Bulletproof Error Handling
Payment engines require total reliability during flaky internet connections, packet drops, or cellular lag. The integration must implement three operational defense layers:

### A. Server-Side Timeout & Retry Policy (Laravel)
When communicating from your Laravel backend to the CyberSource `/uc/v1/sessions` endpoint, wrap the request layer in strict connection rules. Never let a request hang indefinitely.

```php
use Illuminate\Support\Facades\Http;
use Illuminate\Support\Facades\Log;

try {
    // Cut off connection if API takes more than 10 seconds; retry twice before throwing error
    $response = Http::timeout(10)
        ->retry(2, 500)
        ->withHeaders($secureSignatureHeaders)
        ->post('[https://apitest.cybersource.com/uc/v1/sessions](https://apitest.cybersource.com/uc/v1/sessions)', $sessionPayload);

    if ($response->failed()) {
        throw new \Exception('CyberSource Session API returned status code: ' . $response->status());
    }
} catch (\Illuminate\Http\Client\ConnectionException $e) {
    Log::error('HNB CyberSource API Unreachable/Timeout: ' . $e->getMessage());
    return response()->json([
        'error' => 'GATEWAY_TIMEOUT',
        'message' => 'The payment server took too long to respond. Your account has not been charged. Please try again.'
    ], 504);
} catch (\Exception $e) {
    Log::error('Payment Session Exception: ' . $e->getMessage());
    return response()->json(['error' => 'PAYMENT_INITIALIZATION_FAILED'], 500);
}
